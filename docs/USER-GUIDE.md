# 0.5.1 用户交付指南

## AI Agent 自动配置

看板「Agent 接入与 MCP」页能把这台电脑上的 AEC 交给桌面 Agent 协助操作。先启动托盘，打开看板，明确开启本机 Agent 控制，然后复制页面给出的 MCP 配置到支持 MCP stdio 的 Agent 客户端。配置文件格式和位置按相应客户端的正式说明操作；纯云端 Agent 无法直接连接本机接口。看板页内有 Agent 可直接使用的任务提示词。

发布版同时附带 aec-agent.exe，可供自建 Agent host 使用 HTTP/JSON，或让本机 Agent 执行单次 JSON 请求。工具列表、发现文件、认证流程和完整安全边界见 [Agent 接入指南](AGENT-INTEGRATION.md)。

接口默认关闭，只绑定本机。关闭开关会拒绝新请求；退出托盘会停止接口并移除本次随机令牌。Agent 不读取密码；请在本机出口设置页录入。不要给不可信 Agent 授权，也不要把含出口地址、站点或规则的工具结果公开粘贴。

Agent 可帮助管理站点规则、连接第一跳、模式、检查、自启和快捷方式。它不应自动改变用户指定的 ISP IP、删除受保护站点、放宽 DIRECT 或关闭固定出口保护。任何路径切换均可能中断连接；只有当前 ISP 出口再次精确核对通过才会释放。若系统代理发生冲突，请按看板「代理冲突说明」关闭其他客户端的系统代理开关；保留它的本机内核端口作为普通流量上游并继续从该客户端切换节点。

本产品用于 Windows 10/11 x64 的本机 AI 出口控制，包含托盘、mihomo、Rust relay 和配置命令行。用户需要自己的 HTTP/SOCKS5 出口；远程 AI API 网关本身需要另外部署。

## 下载与首次使用

本次交付版为 0.5.1。安装版包含 per-user 安装向导；安装后在一个桌面窗口中使用出口设置、规则/站点、固定出口路径、Agent/MCP 和代理帮助。系统托盘继续独立显示状态并提供恢复、检测和打开看板入口。便携版保留完整功能。以下命令中的版本号和文件名以实际 Release 资产为准。

从 [GitHub Releases](https://github.com/zxs4KHf/agent-egress-controller/releases) 下载 `AgentEgressController-0.5.1-setup.exe` 或 `AgentEgressController-0.5.1-portable.zip`，并核对对应的 SHA256 文件。安装版只安装到当前用户目录，不需要管理员权限；登录自启为可选项且默认关闭。便携版需完整解压到可写目录，保留 `portable.flag`、`bin`、`ui` 目录、应用 exe 和说明文件。桌面控制中心需要 Microsoft Edge WebView2 Runtime；程序不会自动下载，缺失时会提示用户处理。

双击 aec-tray.exe，在首次打开的本机设置页填出口、端口、协议和账号。端口可逐项附协议，例如 `12324/socks5`、`12323/http`；同一候选池的地址必须相同，备用端口用于拨号切换，不表示多个出口。

选目标时区、浏览器语言和精确预期 IP（可留空）。系统代理与时区修改默认关闭，按需分别开启。进入后从托盘启动 Edge/Chrome，让第一个本地检查标签页回报证据。未打开浏览器、证据不足或目标不通时保持黄色；全部硬门槛通过后才开始使用需要稳定出口的账号。CLI 从托盘启动，使用子进程代理环境，现有终端不被改写。

## 直接出口与加密中转

直接连不上出口时可开启隧道。IPRoyal 预设来自 [官方 Shadowrocket 指南](https://iproyal.com/integrations/how-to-use-iproyal-proxies-with-shadowrocket/)，包括 tt01–tt25 的两个端口组合与公开共享参数，仅适合官方支持的 IPRoyal 代理。文档核对日期 2026-10-12，不代表节点当前连通。

路径是「本机 → 加密中转 → 用户出口 → 目标站」，中转入口 IP 与最终出口 IP 不同。隧道路径需要出口用户名/密码；仅用本机 IP 白名单的授权可能拒绝中转服务器。支持自定义 AEAD Shadowsocks 与直连回退，UDP 关闭。回退连接同一出口候选，全部失败时不会把 AI 目标偷偷放成 DIRECT；G1/G2 仍核对真实出口。

## 设置页分流

「全部走出口」把公共请求交给固定出口。「分流」让目标/附加域名走出口，其余直连；填本机日常代理则用「日常代理、DIRECT」fallback 组，每 15 秒健康检查。AI 目标规则在国内分流之前。

GEOSITE/GEOIP 和「国内直连」需要用户自行提供可信的 GeoSite.dat、GeoIP.dat 到 bin 目录。便携包不附带未核实来源的数据文件，程序不自动下载；没有时保持关闭，相关规则预检会报缺项。

## 保留客户端入口与代理共存

退出 Agent 模式后，在设置页「系统级分流 → 本机代理入口端口」填写已有客户端使用的端口；留空或 0 使用默认 17893，其余值须为 1–65535 且不能占用本程序内部端口。保存后下次进入生效。托盘、命令行、检测使用同一设置；较旧页面缺少字段时保留原值。

升级或接替旧链路前，先记录客户端实际使用的入口，备份 data，正常停止旧监听并禁用旧托盘/守护的登录自启，再让新版使用这个入口。不要先停旧入口却让客户端仍指向无人监听的端口。程序不会删除或更改用户级 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY。

如果同时运行另一个代理客户端，关闭对方的「系统代理」开关，保留其内核，并在本程序「分流 → 本机代理」中填写对方的本地监听端口作为普通流量上游。系统代理只交给本程序，AI 站点按规则走固定 ISP，普通流量可走该上游；你仍可在另一个客户端里切换节点，只要不重新开启它的系统代理开关。这样 AEC 连的是固定的本地端口，而不是依赖对方替你改 Windows 系统代理。

不要同时启用另一客户端的 VPN、TUN、透明代理或全局接管开关。这些功能可能改变本机所有流量的路径，包括 AEC 连固定 ISP 的连接，使预期 IP 检查失败或实际出口发生变化。需要切换普通上游节点时，在另一客户端切换节点即可；需要固定 ISP 时保持全局 VPN/TUN 关闭。本程序不合并外部全局绕过清单，国内直连由有序规则控制，避免绕过保护。

## 导入已有表（操作）

先退出 Agent 模式。源 YAML 可带用户自己的密码，不能公开上传。便携目录 PowerShell：

```powershell
.\aec-dev.exe profile import .\my-routing.yaml --dry-run
.\aec-dev.exe profile verify .\my-routing.yaml
.\aec-dev.exe profile import .\my-routing.yaml
.\aec-dev.exe profile check
```

支持出站字段：name、type（http/socks5/ss）、server、port、username、password、cipher、dialer-proxy、udp: false。SS 必须是支持的 AEAD cipher。组支持 name、type（select/fallback/url-test）、proxies、url、interval、tolerance；fallback/url-test 必须显式配置健康检查。名称与引用必须有效，组和拨号链不能成环。

规则支持 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR/IP-CIDR6、GEOSITE、GEOIP，最后一条必须是 MATCH；IP 规则可带 no-resolve。块列表中前置注释和尾注保存到 note；flow 列表不关联逐条注释。MATCH 保存为 final，没有对应注释字段。TLS、插件、其他协议、provider、UDP、未知字段/规则拒绝整次导入，不静默删除。

导入只替换 routing，保留出口、预期 IP、时区、检测和入口；不用源 DNS、TUN、监听端口或系统设置。便携命令默认使用同目录 data，开发默认 runtime/dev-data，可用 `--data-dir <目录>` 指定。原档案备份为 `data/profiles/profiles.json.before-import-*`，原 YAML 不变。

无档案时创建默认档案，出口仍为空，需在托盘设置补齐。密码迁入当前用户 Windows 凭据管理器；保存失败清理本次新增凭据，清理失败明确提示。旧导入留下的凭据不会自动删除，用户可在凭据管理器核对后清理。

设置页对导入表默认「保留现有路由数据」，同时保留现有验收目标。选择内置预设会替换整张表。高级用户可在退出后编辑 profiles.json 的规则数据，不能加入明文密码。

## 托盘切换与桌面应用

select 组导入后可从托盘选择成员，仅 switchable: true 会显示选项。0.5.1 的托盘、看板「快捷出口切换」和 Agent `aec_route` 共用同一逻辑，不再因固定模式统一禁止菜单。切换撤销旧检测就绪、保存 selected 并重载规则，会短暂断开本应用内核的现有连接；重新取得证据后才显示就绪，启动时恢复选择。

例如 OpenAI 组有固定 ISP 与本机代理两个成员，选择本机代理表示明确允许这个组的域名不固定 IP。程序仅调整直接指向此组的 `DOMAIN-SUFFIX` 规则范围：非固定成员移除该范围的保护站点，固定成员重新加入保护，其他站点与预期 ISP IP 不变。普通代理不会自动回退到固定出口；固定验证失败时仍阻断受保护流量，普通出口可独立使用。被更早规则覆盖或受更大父域保护的范围拒绝快捷更改，应在看板整理规则。

规则若直接指向某个出站而不是此组，不会随组切换。精确域名、关键词、Geo/IP 规则不被猜测为可移除的保护范围。至少保留一个检测站点；若要取消所有固定保护，应退出后在设置明确配置，不由快捷按钮隐式完成。重新加入的保护域名默认只做 HTTPS 可达性检查，不假定它支持 trace；独立 ISP 探测仍要求精确 IP。先前删除的逐站 trace 选项如需恢复，可在出口设置中设置；不新增旧版本无法读取的档案字段。

桌面应用是否遵循 Windows 系统代理由应用决定。需要时开启接管；接管门要求显式开启、快照可用、该项无外部写入者，阻止时 G6 为未知。Windows 只有一个系统代理值：本程序接管时，其他客户端不能再开启自己的系统代理开关。若外部程序改写该值，本程序会撤销就绪并告警，不会把它抢回来；请关闭对方的系统代理开关，确认 VPN/TUN/全局接管关闭后，退出并重新进入 Agent 模式。对方内核可以继续运行并切换节点，端口填入「分流 → 本机代理」后作为普通流量上游。全局 VPN/TUN 可能截获本程序的固定 ISP 连接，破坏固定出口保证。

### Claude 桌面版接入与核验

无需托盘启动入口，也不改变 Claude 的安装文件、配置、语言或进程归属。0.3.0 包含系统代理接管、R11 和 `desktop check`。

1. 设置页填写自己的 ISP 出口。需要中转时启用隧道；中转服务器不是最终出口。
2. 选择「分流」，保留附加域名 `anthropic.com`、`claude.ai`、`claude.com`、`claudeusercontent.com`。`DOMAIN-SUFFIX,anthropic.com` 覆盖 `api.anthropic.com`；仅有 `www.anthropic.com` 不覆盖它。AI 域名规则应先于 GEOSITE/GEOIP 和 MATCH。导入表不会自动补规则或被覆盖，需要自己检查 Claude 域名命中的组、成员和固定 ISP 节点。
3. 开启「系统代理接管」，进入 Agent 模式，确认 G6 通过。关闭其他代理工具的系统代理、VPN、TUN 和全局接管开关；仅保留其内核并可在其中切换节点。需要把它作为普通流量上游时，在「分流 → 本机代理」填写其本地监听端口。若 G6 报系统代理冲突，关闭冲突开关后退出并重新进入；程序不会自动抢回。
4. 正常打开和使用 Claude 桌面版。在有请求或长连接期间点「重新检测」，看 R11 的进程 PID、目标域名、预期出站和实际链。ISP 地址/网络身份用 G1/G2 核对，配置了精确预期 IP 才做严格比对。程序不会替用户发测试消息。

也可在便携目录运行以下只读命令；开发环境改用 `cargo run -p aec-dev --bin aec-dev -- desktop check --json --data-dir <目录>`。必须选择实际托盘使用的 `data`，不是另一个测试目录。

```powershell
.\aec-dev.exe desktop check --json --data-dir .\data
```

命令退出码：R11 通过为 0，警告/未知或读取失败为 1，参数错误为 2。它不会写状态、日志、系统设置，不启动、关闭或重启 Claude。托盘完整检测也显示 R11；R11 是只读抽样，不参与绿灯硬门槛。

| R11 结果/原因 | 意义与处理 |
| --- | --- |
| 通过 | 至少观测到一个 Claude 服务域名连接，当前稳定样本的域名规则和实际出站链一致；仅该样本有证据，不代表所有请求或 ISP 身份已经证明 |
| `no_desktop_traffic` 未知 | 未抓到可归属的服务连接；可能空闲、连接已关闭、走别的代理或忽略系统代理，不能据此判定通过或断网 |
| `owned_core_unavailable` 未知 | 当前目录没有可验证的本应用内核/端口，或连接表不可读取；检查数据目录和 Agent 模式 |
| `desktop_probe_failed` 未知 | Windows TCP 读取失败；不把失败当作通过 |
| `desktop_route_unproven` 未知 | 请求只带 IP、域名不可判定，或前置 Geo/IP 规则需要额外匹配证据 |
| `claude_target_not_proxied` 警告 | 观测到 Claude 服务域名走 DIRECT/REJECT；检查规则顺序和组成员，程序保留自定义表，不自动改路由 |
| `routing_mismatch` 警告 | 当前出站链不符合档案，或长连接还在使用切换前的 select 成员；核对组选择并让应用重新建立连接 |

核验只读 Windows 的 IPv4 TCP 表和本应用内核的 `GET /connections`。按客户端源 IP/端口匹配，并要求两次 TCP 读取的 PID、可执行文件路径和进程创建时间一致，控制口及 mixed-port 仍由本应用记录的内核持有。支持 `%LOCALAPPDATA%\AnthropicClaude\app-<数字版本>\claude.exe` 的 Windows 安装形态；Claude Code、启动器、其他安装形态及无法读取身份的进程均不冒充桌面版证据。不读取对话正文、请求头、Claude 配置或令牌，不使用过期日志推断 PID。

Electron 的 [系统代理模式](https://www.electronjs.org/docs/latest/api/structures/proxy-config)使用操作系统配置，但应用可自行覆盖；[代理切换说明](https://www.electronjs.org/docs/latest/api/session#sessetproxyconfig)也指出旧连接池可能继续使用旧代理。没有 R11 证据时先核对 G6 和应用代理设置，必要时由用户自行退出并重新打开 Claude。Node、MCP 子进程、Cowork VM 等路径需分别验收，不用全局环境变量、TUN 或修改 Claude 文件来强制接管。

退出 Agent 模式会恢复已接管的系统代理并停止本应用内核，Claude 仍由用户管理。原有长连接不保证随代理设置恢复立即切换；继续使用时让应用重连。

## 退出、更新与交付

如果 Claude 能登录，但 Code 请求反复 `Request failed`/`Retry`，应核对请求路由与同一时间的 relay 日志；登录成功不代表长请求能持续传输。0.3.0 修复 relay 将拨号/握手超时带入传输阶段的问题，连接成功后不会因这些短超时主动切断等待或流式响应间隔，失败拨号仍受预算限制。更新 relay 后需要正常退出并重新进入 Agent 模式来加载新程序，已有进程不会自动采用新代码；这项修复不等于证明供应商隧道或每个真实 Claude 请求都正常。

退出会请求关闭本应用启动且身份一致的浏览器，按快照恢复已实际接管的项，停止本应用内核与 relay。CLI 由用户关闭。恢复冲突保留外部状态，失败变红，提供重试或明确接受现状；崩溃后先恢复未完成会话，再删数据。

升级入口在托盘与看板「更新与维护」。0.5.1 的「仅更新界面」只安装兼容的版本化页面资源，不停止托盘、relay 或内核，也不改变固定 ISP；完成后点控制中心「刷新界面」，确认放弃未保存草稿后加载。首次从 0.5.0 升级必须先做完整更新，旧程序还没有外部资源读取能力。

「检查完整更新」可在稳定的 Agent 模式或日常模式启动。用户先确认下载，更新器核验项目 GitHub Release ZIP 的 SHA256 与包内清单，再按实际文件哈希判断；如果核心程序或更新器脚本改变，会另行显示连接中断提醒。拒绝停服确认不会停止服务或替换文件。确认后只正常关闭本应用服务，核对恢复完成、内核/relay 停止后备份替换，再按原模式重启；就绪仍需重新检测。恢复失败或文件占用时停止安装，绝不强杀程序。

下载仍是完整便携 ZIP，不是二进制差分包；安装只替换允许且改变的文件，保留 `data\`、用户提供的 GeoSite/GeoIP 和 Windows 凭据。回滚清单及旧文件在安装目录 `.aec-update-backup\`。复制失败自动恢复；纯界面回滚恢复旧活动指针，核心回滚需要先正常退出并确认恢复完成，再按 `rollback.json` 恢复旧文件、删除本次新建文件，不能覆盖或删除用户数据。更新器启动成功不等于更新完成，真实网络是否可用以检查证据为准。

0.5.0 之前的版本没有更新入口，首次升级需要手动下载完整 0.5.1 ZIP 和校验文件。旧便携版用户先正常退出并确认恢复完成，备份整个旧程序目录；把 ZIP 解压到临时新目录，进入其中的 `AgentEgressController-0.5.1-portable` 文件夹，将里面的程序文件复制到旧安装目录并允许覆盖。不要删除或覆盖旧目录的 `data\`、用户放入 `bin\` 的 GeoSite/GeoIP 文件；`portable.flag` 保持存在。完成后从旧目录启动 `aec-tray.exe`。如果改用安装 EXE，它会使用 `%LOCALAPPDATA%\AgentEgressController\` 作为独立数据位置，不会自动迁移旧便携目录的 `data\`。旧模板档案在读取时转换，保存才更新。换 Windows 用户或机器需重新填写密码，`credentialRef` 不能替代跨机器密码。

给其他用户交付全新 zip、SHA256SUMS、无私人凭据的路由示例和自己的服务说明。不要交付维护者 data、浏览器 profile、日志、快照、真实出口或带密码 YAML。内核/relay 启动时会使用临时凭据配置，正常退出会清理；崩溃后需先恢复，不能把运行中的 core 目录当作无敏感信息的示例。仓库 `crates/aec-core/tests/fixtures/routing.yaml` 是纯合成示例，不能直接联网。

卸载前关闭登录自启、退出并完成恢复，移除桌面和开始菜单的四个 Agent Egress 快捷方式，再删目录；凭据条目以 AgentEgressController: 开头，可手动清理。排查提示词只复制、不自动发送，分享前自行决定是否遮盖 IP。

## 看板与固定 ISP 保护

托盘「打开看板」管理受保护站点和有序规则。类型、出站、不解析 DNS 都有选项，常用站点和 Geo 分类提供建议；网站、IP 段和自定义类别仍由用户填写。类别是否存在取决于 GeoSite/GeoIP 文件，保存或内核预检失败会报错。可新增、移除、上下移动规则，最后兜底单独选择。已有注释保留，普通规则不能覆盖受保护域名及子域名。

首次启用固定出口保护：先退出 Agent 模式，在设置填写精确预期 IP，再到看板保存连接路径，然后进入。可选择直接连接 ISP、官方隧道自动选择或具体节点。经隧道失败的候选之后，可尝试直接连接同一组 ISP 出口代理；这不是切换到另一个 ISP。最终只在独立探测确认精确预期出口后放行，无法确认则阻断。

运行中切换或保存规则先选择 REJECT 并断开本应用内核的旧连接，再选择第一跳/重载规则，经独立 probe 入口核对精确 IP，成功后放行；失败保持阻断。阻断操作本身失败会通知，不宣称已安全阻断。巡检约每 30 秒执行；供应商在两次检测间改变 IP 仍是风险。只覆盖通过本程序并匹配保护规则的流量，普通 DIRECT、忽略系统代理的进程不属于保护范围。

短暂中断后不必反复重启托盘：后续巡检取得精确匹配证据，才重开已保存的第一跳、再次核对同一出口并刷新完整检测。重开失败或证据不匹配/未知继续阻断，不切换 ISP，也不在固定出口未验证时改动系统代理。健康连接不重新选择路径或关闭。若只是某个站点的检测临时失败，出口仍精确匹配时也会刷新完整报告；硬门槛仍未通过则继续显示未验证。也可在托盘点击「重新检测」立即重试。

已有站点的 trace 检测方式保留；新站点默认 HTTPS 可达性检查，没有网站 trace 就不声称该网站证明出口。固定保护另外使用强制走 ISP 的 Cloudflare trace，不沿用系统代理的分流结果。

资源根域不一定提供 HTTPS 服务。`oaiusercontent.com` 的可达性使用 OpenAI 文档中的 `files.oaiusercontent.com`，DNS 路由证据也核对该实际主机；保护规则仍覆盖 `oaiusercontent.com` 及所有子域名，不缩小范围。404/403 表示 HTTPS 服务回答请求，不代表文件上传或账号操作成功；连接失败仍为失败。来源：[OpenAI 网络建议](https://help.openai.com/en/articles/9247338-network-recommendations-for-chatgpt-errors-on-web-and-apps)。

## 自启、快捷方式与便携目录

托盘和看板均有「登录时自动启动」开关。只写 HKCU Run 的 `AgentEgressController` 值，命令为本安装 `aec-tray.exe --enter`；不安装服务或任务。登录后自动尝试进入，但上次未恢复和接管门仍会阻止进入或真实写入。自启默认关闭。

从托盘或看板点「创建桌面和开始菜单快捷方式」，在当前用户桌面和开始菜单 Programs 下各建两个入口：`Agent Egress Controller` 打开托盘，`Agent Egress Dashboard` 打开看板。已有托盘时看板请求交给该实例。开始菜单可搜索 Agent Egress。

任务栏分组修复后，控制中心和看板快捷方式共用独立的 `AgentEgress.Controller` 标识，使用自己的盾牌图标，不归到启动它的 ChatGPT/Codex 图标里。任务栏重新打开会转交托盘取得新的本机认证会话；固定项不保存临时令牌。旧版控制中心已关闭、程序文件已更新后，可从同一安装运行 `aec-control.exe --create-shortcuts all` 修复入口；此命令不启动或停止网络服务，也不改分流、自启或凭据。安装包按用户所选桌面/开始菜单组件创建相同标识的入口。

若之前手工固定的 **Agent Egress 旧入口** 仍有缓存，可取消固定该旧入口，再从新版看板窗口重新固定。不需要取消固定 ChatGPT，也不需要重启网络内核或清理整个任务栏。

命令行可用 `aec-tray.exe --enable-autostart`、`--disable-autostart`、`--create-shortcuts`、`--dashboard`。注册或同名快捷方式属于其他安装时拒绝覆盖；在旧安装先关闭自启，核对并移除旧入口，再在新目录重新创建。移动便携目录前也按这个顺序处理。不开文件关联、URL 协议、系统服务或全局环境变量，避免让不必要的系统注册残留。

托盘运行时，同一安装的 `aec-dev` 会拒绝重检、恢复或其他写入命令，避免第二个进程覆盖会话状态。请用托盘的「重新检测」和「恢复上次未完成的会话」；托盘退出后锁自动释放，异常退出也不留下失效的 PID 锁。
