# 升级到 0.5.4

下载入口：[v0.5.4 Release](https://github.com/zxs4KHf/agent-egress-controller/releases/tag/v0.5.4)。新版增加多个本机上游管理，沿用组件级增量下载：按本机文件哈希，只下载变化的组件，不是字节级二进制差分。上游管理等核心功能仍需完整程序更新，**仅更新界面不会安装这些功能**；核心更新仍需用户单独确认停服。

| 当前版本 | 升级方式 |
| --- | --- |
| 0.5.1 / 0.5.2 | 原更新器可全量升级一次；若本次就要增量，先按下方引导替换脚本 |
| 0.5.3 及新版更新器 | 自动比较哈希、显示组件数与字节预算；只下载变化组件 |
| 原版 0.5.0 | 先按下方步骤替换一次更新脚本，再从原托盘「检查并安装更新」升级 |
| 早于 0.5.0 | 没有更新入口，按[用户指南](USER-GUIDE.md#退出更新与交付)手动升级 |

## 0.5.1 / 0.5.2：直接使用原更新器

1. 保存控制中心草稿。在托盘或看板「更新与维护」选择「检查完整更新」。
2. 确认下载。更新器从本项目 GitHub Latest Release 获取完整 ZIP 和同版本 SHA256 文件，并核验包内清单。
3. 出现核心停服确认时，选择方便短暂断网的时间继续。取消不会停服或替换文件。只正常关闭本应用的托盘、控制中心及网络子进程，不强杀其他程序；恢复不完整或文件被占用则中止。
4. 更新器备份并替换程序、按原模式启动托盘；是否联网就绪仍以重新检测为准。
5. 从托盘点「创建桌面和开始菜单快捷方式」，再打开看板。更新器不会自动重写旧快捷方式或任务栏固定项。如果旧固定入口仍有缓存，只取消固定旧的 Agent Egress 入口，再从新看板固定；不要取消固定 ChatGPT。

更新不重置规则、出站组选择、固定 ISP、端口、凭据或登录自启。若用户原先设为 OpenAI 走本机日常代理、Claude 走固定 ISP，升级保持这些选择，不切换 ISP IP。

## 一次性更新器引导：让本次升级就用增量

0.5.1/0.5.2 的原脚本只认识完整 ZIP，新 Release 不能远程把旧程序变成增量更新器。原版 0.5.0 还存在包路径白名单限制（不认识图标/UI/中文说明），因此必须引导。不关闭校验、不改写旧 Release。

1. 关闭正在运行的更新检查窗口。无需为了复制脚本停止网络服务。
2. 从同一个 v0.5.4 Release 下载 `aec-update-0.5.4.ps1` 和 `SHA256UPDATER-0.5.4.txt`。这份脚本与完整 ZIP 里的 `aec-update.ps1` 字节一致。
3. 在下载目录打开 PowerShell，核对 SHA256。下面只校验，不运行下载的脚本：

   ```powershell
   $actual = (Get-FileHash -LiteralPath '.\aec-update-0.5.4.ps1' -Algorithm SHA256).Hash
   $line = Get-Content -LiteralPath '.\SHA256UPDATER-0.5.4.txt' -Raw
   if ($line.Trim() -notmatch '^([a-fA-F0-9]{64})\s+\*?aec-update-0\.5\.4\.ps1$') { throw '校验文件格式错误' }
   if ($actual -ne $Matches[1]) { throw 'SHA256 不匹配，不要安装' }
   'SHA256 核对通过'
   ```

4. 找到**实际正在使用的安装目录**（包含 `aec-tray.exe`）：把原 `aec-update.ps1` 复制为不重名的备份，再把下载脚本复制到这个目录并命名为 `aec-update.ps1`。仅替换这一份脚本，不动 `data`、`portable.flag`、程序或凭据。不要双击脚本，也不要覆盖另一份安装。
5. 0.5.1/0.5.2 从原托盘选择「检查完整更新」，不必先停网关；原版 0.5.0 菜单只在日常模式可用，必须由用户主动退出 Agent 模式并确认恢复完成后再启动更新。
6. 新脚本读取小型清单，显示组件下载量和完整包大小；用户同意下载后验证所有文件，再另行请求停服确认。确认后才原位备份替换并启动托盘。0.5.0 不传恢复模式参数，升级后手动进入 Agent 模式。

如果不希望替换脚本，可按用户指南备份后手工升级完整 ZIP。不要直接把便携数据搬到一个全新的安装 EXE 目录：便携与安装版的数据位置不同，安装器不自动迁移。

## 备份、回滚与边界

### 增量下载边界

每个程序、内核、更新器和 UI 各是一个组件，其余文档/许可证/图标是资源组件。一个组件中任意文件变化就下载整个组件；未变化组件不下载。UI-only 只选择 UI，既不下载也不替换核心。小型清单/校验文件在计划阶段获取，下载负载仍要用户确认。无增量清单的旧 Release 会说明原因并询问全量；损坏清单/组件则失败，不静默降级。暂不提供断点续传或缓存，失败重试会重新下载本次所需组件；节省比例取决于实际改动。

### 弹窗关闭后，Agent 直接查日志

0.5.3 更新器在首次网络请求前建立 `数据目录/update-logs/<标识>.json`，保存最近 20 次、每次最多 64 条事件。每条含 UTC 时间、阶段、状态、错误码与数值 HTTP/native code；会话另有版本、增量/全量、预算和已完成下载字节。程序目录和数据目录不同的安装版使用 `%LOCALAPPDATA%\AgentEgressController\update-logs\`；便携版使用安装目录 `data\update-logs\`。

```powershell
.\aec-agent.exe update-status
# 数据目录不同或使用独立解压的新版诊断程序时：
.\aec-agent.exe --data-dir 'C:\Path\To\data' update-status
```

无需托盘运行、API 开启或联网；不弹窗、不更改文件、不重试更新。MCP/鉴权 HTTP 调用 `aec_update_status`，参数 `{}`。只更新脚本但 Agent 仍是旧版时，可先直接读取日志 JSON。`sessions[0].events` 的失败项含 `nextAction`；`downloadedBytes` 计成功下载文件（含元数据），不计中断请求的部分字节或协议头。无日志不能推断没有出错；未终结记录不能证明更新器仍在运行。旧版未留日志的历史错误无法追溯，不能补造原因。

更新器在安装目录 `.aec-update-backup/<时间戳>-<标识>/` 保存旧程序和 `rollback.json`。失败复制会自动恢复；新版托盘启动失败时尝试回滚并打开旧程序。手动回滚前先正常退出并确认系统恢复完成，再按清单恢复旧文件、移除此次新增文件，保留 `data`、用户 Geo 文件和凭据。快捷方式修复是独立操作，不包含在程序文件回滚清单内。

程序未签名；SHA256 只能检查与本项目发布资产是否一致，不能代替可信来源判断。升级成功不能证明供应商链路或账号可用。全局接管和固定出口保护保持原约束，未知出口不会被当作通过。Agent 能打开更新器，不能替用户确认停服。
