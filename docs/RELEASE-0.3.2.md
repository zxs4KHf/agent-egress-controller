# 0.3.2 固定出口恢复与会话一致性验收

日期：2026-10-13。此版本把固定出口自动恢复、同一 ISP 候选回退及单写入者约束合并到 0.3.2。用户级入口端口默认仍为 17893；已有安装可以显式配置，不更改 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`。

## 行为

- 固定出口巡检发现证据丢失时先阻断受保护传输链。只有取得与精确预期出口匹配的证据，才选择已保存第一跳、再次核对并放行。失败或未知继续阻断，不改出口身份。
- 固定出口已经核实时，若先前站点硬检查失败，巡检重新执行完整报告；这会更新就绪状态，但不重选路径或断开健康连接。
- 隧道候选按序尝试后，可以尝试配置的 ISP 同一出口代理直连候选。所有路径均须匹配精确预期 IP 才放行；不会将站点交给任意 DIRECT 规则。
- 固定出口阻断只删除经过该传输链的连接。内核连接表不可读、缺字段或无法核对时返回错误，不宣称其他连接已保留/关闭。
- 系统代理周期巡检发现外部更改时保留外部值、撤销 G6/就绪并通知，不与其他程序争写。用户关闭冲突开关并重新进入后重新取得 G6 证据。
- 托盘持有 OS 独占会话锁；对同一数据目录运行的 `aec-dev` 写命令不能并发覆写。只读诊断可用；进程结束或崩溃自动释放锁。

## 自动化验证

已验证命令：

```text
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
cargo test -- --include-ignored
```

结果：格式和 Clippy 通过；核心 192 项、CLI 集成 3 项、relay 链集成 2 项、托盘 7 项，合计 204 项测试通过，0 失败。真实 mihomo 集成测试已包含在内。

针对状态覆盖的集成回归先运行失败：`cli_mutations_cannot_overwrite_an_active_session` 输出 `CLI must refuse to mutate a tray-owned session`。加入 OS 文件锁后通过；测试覆盖 `ack`、`recheck`、`exit`、`enter`、内核变更、档案初始化均被拒绝且原状态逐字节不变；只读状态可读；锁释放后恢复命令可运行。

其他回归包括固定出口的失败后恢复、错误/未知证据不恢复、第二次探测或重开失败保持阻断、健康连接不重选；系统代理外部改写不产生竞争写入、G6 同步并在原值恢复后重新就绪；connection report 缺失、格式错误或缺字段时阻断操作失败，不全局断连；relay 池隧道及同一 ISP 直连候选顺序。

## 维护者机器观察边界

维护者本机通过已保存的 localhost 入口分别请求 ChatGPT、Claude 和独立固定出口探测；三个请求的出口检查均与档案精确匹配。托盘在运行期间的完整站点检测偶尔仍记录单站点 `connect_failed`，因此不能宣称每次 G2 都稳定通过或真实用户会话已验证。0.3.2 现在会在精确固定出口仍有效时重新刷新这份报告；未通过的硬门槛仍维持 `agent_unverified`。

没有自动发送 Claude/Codex 消息，没有观察真实登录或会话内容。网站 HTTP/trace 连通不证明账号操作成功。其他机器的 ISP 可用性、网络质量、隧道延迟与 Windows 全局状态写入须分别验收。

## 回滚

源码回滚通过新的 revert commit；不改写远程历史。二进制回滚时先从托盘正常退出，保留运行数据，恢复当前安装目录原有三个可执行文件备份，再用原登录入口启动。禁止把旧托盘/guard 同时设为系统代理写入者。原 0.3.1 发布包及回滚 tag 不覆盖。
