# 0.5.7：更新占用与临时下载故障修复

0.5.5 实机日志显示：一次增量更新在组件下载阶段失败；同一下载尚未结束时，多次点击更新产生 `update_busy`。原脚本还会在失败/成功结果弹窗打开期间继续持有更新锁，导致工作已经结束后仍不能重试。

## 行为

- 所有终结结果先完成日志和必要恢复，再释放更新锁并显示弹窗。保留结果窗口不再阻止重试。
- 真正已有更新运行时，重复请求说明“更新正在进行”，记录 `complete/cancelled/update_busy`，不并行执行、不停止服务。
- 临时连接中断、超时和 HTTP 408/429/500/502/503/504 最多下载三次，等待一秒、两秒。每次重试保留阶段、错误码和 HTTP/native code，耗尽后保留最终失败。TLS、DNS、权限、清单、哈希错误不盲目重试或绕过验证。
- 仍按组件增量下载；不提供断点续传或长期缓存。下载成功不等于安装成功，安装成功不等于网络就绪。

## 验证

`packaging/test-incremental-update.ps1` 通过真实更新入口与隔离 HTTP 服务验证：失败结果弹窗期间另一个线程可取得锁；更新运行期间第二请求安全退出；HTTP 503→200 自动恢复并核验字节；持续 503 三次后终结失败；404 不重试；取消下载/核心更新不调用真实生命周期。测试保留日志，Agent 可离线查询。

仓库必需检查为 `cargo fmt --all --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`；发布验收另外包含 pinned mihomo、历史更新兼容与 GitHub Windows CI。实际结果以 PR/CI 记录为准。

## 升级与回滚

旧脚本不会自动获得本次修复。先从同版本官方 Release 取得独立脚本和 SHA256 校验文件，按 [升级指南](UPDATING.md) 备份并替换 `aec-update.ps1`，无需停网关；再从原托盘启动完整更新，下载核验后单独确认停服。不要覆盖运行中的 EXE，不要删除互斥对象或强杀更新器。

更新保留用户数据、凭据、选定站点和固定 ISP 身份；仅正常停止本安装程序，备份在 `.aec-update-backup`，失败走既有回滚。普通流量仍采用用户当前配置，不强制 GPT 绑定某个代理上游。Arena 和指纹浏览器的独立出口不接管。
