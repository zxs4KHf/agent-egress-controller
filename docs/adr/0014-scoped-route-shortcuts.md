# ADR-0014：固定保护下的显式分组快捷切换

## 背景

固定模式把受保护域名的 relay 规则放在普通路由之前。旧托盘仅修改 select 组不能覆盖这些规则，因此禁用菜单并要求用户去看板。这阻止了用户明确选择某个服务使用日常代理的快捷操作。

## 决策

托盘、看板、MCP/HTTP 共用串行 Worker 和纯函数切换计划。只允许选择现有可切换组的成员。仅直接指向该组的 DOMAIN-SUFFIX 规则定义自动管理的保护范围；非固定选择移除此范围的保护站点，固定选择重新加入。预期 ISP IP、第一跳与其他受保护域名保持不变。

切换撤销旧就绪、固定模式先阻断、保存档案并重载规则，关闭旧连接；独立出口探测成功才恢复固定流量。普通成员不因固定出口验证失败被错误报告为未切换。重载失败回存旧档案并报告恢复结果，不宣称网络已恢复。

对被更早规则覆盖、受更大父域保护或无效配置拒绝切换。至少保留一个检测目标。新加入的保护站点使用 trace=false，不假设网站实现 Cloudflare trace；已有未移除的站点保留其检测属性。独立固定出口探测始终保留精确 IP 检查。

## 备选与否决原因

- 继续禁止托盘切换：违背用户一键操作需求。
- 只 PUT 选择组：高优先级保护规则仍抢先匹配，按钮显示改变但实际流量不变。
- 全局关闭固定保护或更换期望 IP：扩大用户只针对单个服务的授权范围。
- 由 Geo/IP/关键词规则猜测域名保护范围：不能可靠证明边界，可能误取消其他站点保护。
- 在 RoutingGroup 新增保存检测属性的字段：旧版本严格拒绝未知字段，会破坏二进制回滚。保持既有档案 schema；重新加入站点的逐站 trace 如有需要由用户在设置中恢复。
- 保留旧长连接：会继续使用切换前出口，无法实现清晰的切换语义；接受短暂断连。

## 验证

纯计划测试覆盖域名范围、父域冲突、规则覆盖、固定保护往返与预期 IP 不变。pinned mihomo 的 loopback 集成测试验证普通出口在 relay REJECT 下仍可用，切回固定出口在重新放行前不能通过。Edge 测试验证看板按钮与草稿保护，Agent schema 拒绝额外强制参数。
