# ADR-0004：全局状态写入走适配器，并设接管门

- 状态：Accepted
- 日期：2026-10-10

## 背景

系统代理（HKCU Internet Settings）和系统时区都是整机只有一份的全局状态。2026-10-10 只读核查发现：

- 当前 `ProxyServer = 127.0.0.1:7893`，指向旧项目的 mihomo；当前时区 `Eastern Standard Time`，是旧项目的 agent 模式。
- 旧项目的 `startup-egress.ps1` 每次登录都会把系统代理改回内核；旧托盘可以切换系统代理和时区；旧 guard 每 30 秒拉起一次链路。

所以只要新项目写这两项，就会修改旧项目的代理状态，并且和旧项目的写入者互相覆盖。新项目进入 Agent 模式前拍的快照，记下的也是旧项目的状态，而不是用户真正的日常状态。

## 决策

1. 系统代理、时区等全局写入一律通过可插拔适配器完成。每个适配器提供 `read`、`plan`、`apply`、`verify`，并区分 `real` 和 `dry-run` 两种执行模式。
2. 开发和测试期默认 `dry-run`：真实读取，模拟写入，写入计划进日志和测试断言。显式启动入口（进程级 `--proxy-server`、子进程环境变量）不碰全局状态，可以真实测试。
3. 真实写入受「接管门」控制。全部满足才开门：
   - 用户在设置里显式开启「接管全局状态」；
   - 没有检测到外部写入者，包括旧项目的 guard/托盘 mutex（`Local\AIEgressGuard`、`Local\AIEgressModeTray`）、指向其他目录的自启动项、运行中的其他代理客户端；
   - 进入前快照已成功写盘。
4. 接管门关闭时，依赖全局写入的检查项报告为「未知」，原因写明「全局状态未接管」，因此不会显示「Agent 模式已就绪」。
5. 运行期间发现全局状态被外部改写时，只告警，不反复改回，避免和其他程序互相覆盖。

## 后果

- 首个垂直切片只能真实验证显式启动入口；系统代理和时区的真实写入，要等 legacy 迁移（ADR-0006）完成、新产品替换 legacy 之后再验收。
- 适配器边界让状态机可以用假适配器做单元测试。
- 拒绝了「新项目直接写全局」：会违反 ADR-0001，也会让快照记错。
- 拒绝了「只在虚拟机里测」：需要管理员权限启用 Sandbox/Hyper-V，成本高；以后可以作为补充验收手段。
