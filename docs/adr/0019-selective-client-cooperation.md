# ADR-0019：保留用户系统代理入口，仅协作转发固定站点

状态：需求与范围已接受，适配器实现待隔离验证。日期：2026-10-16。

2026-10-17 实现进展：固定专用入口、局部脚本、UDP / DNS 失败关闭已通过隔离双内核验收；客户端持久挂载及运行核对仍未实现。浏览器环境的两范围预览、确认和恢复已实现，策略只支持普通 Edge；为避免影响用户独立指纹浏览器及其 Chrome 回退路径，不写任何 Chrome / Chrome for Testing 全局策略。不能把独立 profile 当成产品级策略隔离。选择此窄范围而不是直接覆盖两个产品，是为了保留指纹实例的代理与语言控制权；如指纹浏览器改用 Edge，全局范围也不再适用。真实浏览器证据与配置保存分开。

用户不再要求 GPT 固定使用 XxYun，改为保留当前系统代理和其他节点的使用习惯，仅把选定站点（优先 Claude/Anthropic）锁到原 ISP。采用显式授权的站点协作分流：由支持规则的当前代理客户端将选定域名转交 AEC，AEC 核对原固定身份；其他规则、节点及 Arena 独立指纹浏览器不接管。不能循环抢写 Windows 系统代理，也不为节点变化反复更换 AEC 入口端口。

这是 ADR-0004 的新协作模式，不把原来“不生成外部规则”的限制当作已经实现的能力；同时对 ADR-0001/0017 的既有服务隔离作窄例外：仅管理明确标记且有所有权证据的规则块，先展示差异、备份受管块、校验、可恢复；不接管整个订阅、内核进程或系统代理。配置重载可能中断连接，必须事先说明并取得必要确认，不能把“允许管理规则”解释成“随时允许停网关”。

## 安全条件

- 规则只含用户选定域名及子域，不自动扩展到 GPT、Arena 或全部 AI。选定站点在 AEC 不可用、固定身份未知或不匹配时连接失败，不回退到普通节点或 DIRECT。
- 先验证客户端能力、规则优先级、UDP 行为、反向链路与循环；不能只因为存在 HTTP 转发出站就声称 fail-closed。无法证明安全的客户端显示不支持/未知，不静默改成系统接管。
- 普通流量遵循当前系统代理客户端原规则；独立指纹浏览器的 profile 与出口由用户管理。
- 浏览器设置提供「仅 AI 浏览器」和「全局浏览器」两个范围。全局范围针对明确支持的浏览器先展示现值、目标、策略冲突、影响与恢复条件，用户确认后才应用。不自动读写聊天、Cookie 或登录态。
- 浏览器策略可能影响同一产品下的所有 profile；每项策略必须按实际能力说明范围，不能声称所有语言、DNS、WebRTC 和时区设置都能按网站独立应用。Edge 的部分 WebRTC 策略支持按 origin，系统时区仍是整机状态。无法可靠排除指纹浏览器时必须告警并停止对应全局变更。
- 系统时区仍受原接管门约束；语言、DNS、WebRTC/UDP、EDNS 分项报告证据、作用域和时间。缺少观测能力、无 ICE 候选、STUN 不通或未查到 EDNS 证据都是未知，不伪造通过。

## 未采用的方案

- 抢回系统代理：破坏用户保留当前入口的要求，无法真正共存。
- 永久把 GPT 绑定 XxYun：用户已经撤销此要求，端口和供应商不能硬编码。
- 对整个 Edge/Chrome 直接阻断其他代理端口：会影响非保护站点及潜在的独立 profile，不能作为域名级协作的默认实现。
- 只写运行中内核配置：可能被订阅刷新覆盖；缺少持久化和运行证据时不能显示“已保护”。
- 仅替换 DNS 服务器或隐藏 G3 警告：不能证明解析走了固定出口，更不能等同于整机无泄露。
