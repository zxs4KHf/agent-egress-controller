# ADR-0016：组件增量下载与离线更新证据

用户不接受每次下载完整包，也不能依赖用户保留错误弹窗才能排查。旧更新器仅按哈希减少替换文件，但网络仍全量下载；失败只显示 MessageBox，关闭后证据丢失。

决定按文件 SHA256 选择组件：五个程序、mihomo、更新器、UI、其余资源分别压缩。版本清单给出组件与逐文件大小/哈希，仅接受同一个官方 GitHub Release 的资产，不接受清单指定任意 URL。无需保存每个历史版本的二进制补丁：自定义修改和缺失文件都能按实际哈希判断，通常能跳过最大且固定的内核。否决只把“少复制文件”称作增量下载；否决版本号相等即信任本地字节；暂不采用多基线二进制差分，避免重建复杂度与损坏基线风险。

下载组件后完整验证，结合已验证未变化本地文件重建暂存目录，复用备份/安装/回滚。UI-only 可用仅包含 UI 的暂存目录，不能选择程序。清单缺失可以明确询问全量；清单损坏、哈希不符或未知 schema 直接失败，不能静默降级。下载计划不授权停服。组件模式没有断点续传或长期下载缓存，不保证所有更新节省同一比例。

在查询 Release 前初始化结构化日志，原子替换单次会话 JSON，保留 20 次且各最多 64 事件。受控阶段/错误码、数值 HTTP/HRESULT、公开版本与字节数足够区分查询、下载、校验、等待确认、停服、安装、回滚、启动问题；禁止原始异常、URL、响应正文与参数进入日志，优先消除秘密而非依赖事后正则。Agent 读取时再次白名单筛选；检查过 prompts::redact，其通用脱敏不是任意异常文本可安全持久化的保证。

离线 CLI 可在托盘/API 不可用时读取日志；HTTP/MCP 使用既有鉴权接口新增只读工具，不改变页面资源契约，所以 UI 协议保持 2，旧页面仍可运行。没有新接口页面依赖。否决让 Agent 根据 launched 推断 installed，否决关闭弹窗即丢失诊断，否决日志错误阻止已需要的恢复。

0.5.7 将互斥锁的生命周期限定到实际工作与确认阶段：终结日志和安装/恢复完成后，先释放锁再显示结果。理由是结果弹窗没有工作可保护，却会让重试持续 `update_busy`。真正并发的请求仍不得执行，记为取消并提示等待；否决删锁、强杀或取消互斥来“修复”。下载暂时网络错误有限三次重试并保留中间证据，永久故障和字节校验错误保持失败；否决无限重试和静默换路由，因为它们掩盖故障或破坏用户出口选择。

旧 0.5.1/0.5.2 更新器不会自动识别新元数据：全量升级一次，或用户先校验并替换独立脚本，本次即可增量。0.5.0 原白名单限制仍需引导。所有原发布资产不改写。此次不部署或重启维护者的生产网关；隔离合成数据、固定历史脚本、真实历史 ZIP 与 GitHub Windows CI 负责验证。
