# ADR-0007：检测服务只自动调用有公开说明的接口，其余给手动链接

- 状态：Accepted
- 日期：2026-10-10

## 背景

用户希望参考 `https://ip.net.coffee/` 这类检测网站，有接口就引用，没有就给链接让用户自己测。2026-10-10 下载了该站点前端源码，并对接口做了实测：

- 站点自用接口 `/api/geoip/{ip}`、`/api/iprisk/{ip}`、`/api/dns/result/{token}` 都能返回 JSON，CORS 为 `*`。但它们没有公开文档，`robots.txt` 明确写了 `Disallow: /api/`。
- 它的前端还调用了几个有公开说明的接口，实测可用：`https://1.1.1.1/cdn-cgi/trace`、目标站自带的 `/cdn-cgi/trace`（`claude.ai`、`www.anthropic.com`）、`https://api.ip.sb/geoip/{ip}`、`https://ipwho.is/{ip}`。
- DNS 泄露检测要靠服务端自建权威 DNS 和随机子域名，没有公开、稳定的 API。

## 决策

1. 默认自动调用的服务：
   - 固定出口的证据：目标域名自带的 `/cdn-cgi/trace`（SPEC G1）；
   - 直连 IP 和非目标流量出口：`www.cloudflare.com/cdn-cgi/trace`。2026-10-11 修订：原先用的 IP 字面量 `1.1.1.1` 在本机直连会超时，改用域名形式；
   - ASN 和地区复核：`ipwho.is/{ip}` 为第一来源，`api.ip.sb/geoip/{ip}` 复核（它直连会返回 403）。
2. 服务列表是可编辑的配置，每项写明来源、用途、请求方式、超时和解析字段。
3. ip.net.coffee 的首页、`/claude/`、`/dns/`、`/webrtc/` 只作为「手动测试链接」，由用户在 Agent 浏览器里打开；应用不调用它的 `/api/`。
4. DNS 路径门槛用本地证据判定（mihomo 连接记录里目标域名是按域名而非 IP 出站、命中预期策略组，以及 DNS 监听状态）。外部 DNS 泄露检测只给手动链接。
5. 仅本地模式不调用第三方检测服务，但仍然请求档案里的目标域名（那是用户本来就要访问的地址），所以出口 IP 可以从目标站 trace 获得，ASN 显示为「未知」。

## 后果

- 自动检测不依赖可能随时失效、也没有授权的私有接口。
- 第三方给出的风险标签（如是否机房 IP）第一版不自动获取；用户需要时，用手动链接自己查看。
- 服务变更时只改配置，不改代码；服务失败、超时或返回不一致时，检查项状态为「未知」或「警告」，不当作通过。
