# ADR-0020：协作入口只观察，不继承 AEC 系统代理接管

状态：已实现，候选 0.5.8；生产切换独立验收。日期：2026-10-17。

## 问题与证据

仅导出或安装规则没有改变旧 profile 的系统代理接管含义。Clash 系统开关和 AEC 旧模式同时使用时，用户观察到开关顺序影响访问、Claude 跟普通节点离开。现场只读探针确认 CVR 2.5.8 使用 Windows named pipe、TCP controller 为空，旧适配器拒绝；当前运行配置缺少 `AEC-MANAGED-FIXED`。内部固定入口可访问不证明浏览器经过它。

## 决策与理由

- 将两个入口方式作为平等的单选项：客户端系统代理开启时安装并激活站点转发；客户端系统代理关闭时由 AEC 本地接管，并使用本机普通上游。理由：用户需要保留现有网络/隧道收益，同时能选择是否改 Clash 规则。放弃把 AEC 接管隐藏为低优先级“兼容模式”或把规则协作当唯一流程：会误导用户重复配置，旧入口能力已满足一部分用户。现有 explicit-only 配置不自动选择任意方式；保存不立即切换网络。
- 用安装级 `clientCooperation` 明确协作工作方式，并与 AEC 系统代理接管互斥。控制器以此字段阻止系统代理写入，即使残留旧 profile 也不能抢入口。缺字段为 false，避免悄悄改变已部署网络。放弃根据进程/端口自动切模式：会改变用户的全局状态及恢复语义。
- 使用现有 CVR named pipe，只读、绑定服务端 PID/创建身份与配置摘要。保留既有已认证 loopback TCP 兼容。放弃要求用户新开 TCP、猜密钥、自动重载：增加暴露且会改变运行环境。
- G7 独立检查当前系统入口、排除项、Rule 模式与有序转发规则，约五秒观察；关闭/改道时撤销保护，重开后读取新规则。放弃用内部 ISP/G3 代替真实客户端入口：两者的请求路径不同。客户端端点/DNS API 缺证据仍 unknown，不能伪造绿色就绪。
- 协作规则只使用明确选中的域名。放弃自动补齐服务域名族和自动删除旧 GPT 项：范围变化须用户可见。AEC 内部兼容模式原 Claude 家族保护仍保留，但不会扩大外部客户端受管列表。
- 保留 Clash 系统代理的单一所有权，启动顺序不限，但日常浏览器仍依赖该入口。放弃开关关闭时自动抢回或启用 TUN/防火墙：不符合用户保留普通代理习惯与当前仓库边界。此方案不是系统级绝对防绕过，关闭入口、Global/Direct、脚本引擎回退及独立代理不在保护保证内。

## 交付与恢复

升级核心、日常状态选择协作、核对站点、持久安装、Clash 官方 UI 激活、运行核对分别验收。重载或停服要先说明影响并取得授权。回滚保留旧 settings/profile 及安装备份；撤销未变化的受管 footer 后在 Clash 激活，普通规则不改。若外部脚本已编辑，停止自动恢复，不能覆盖。
