# ADR-0006：用可执行 Runbook 把旧出口链路原样迁入唯一工作目录

- 状态：Accepted（补充 ADR-0001）
- 日期：2026-10-10

## 背景

ADR-0001 规定旧目录和运行中的服务只读，未来整合必须先有可回滚迁移方案，并由用户单独确认。2026-10-10 用户要求：写一份可执行的 md 文档，让其他 agent 能在网络环境服务关闭后照着执行，把整体依赖全部迁移到唯一工作目录 本仓库。

## 决策

1. 迁移方案写在 迁移 Runbook（维护者本地文档，不随仓库发布）。这就是 ADR-0001 要求的「可回滚迁移方案」；真正执行切换前，仍要用户在对话里单独确认。
2. 迁移形态是「legacy 原样搬」：旧的出口链路放进新目录的 `legacy/`，保持原端口（7893/9099/10553/12325）和原 mutex 名。客户端、shim 和 MSIX 应用都不用改；同名 mutex 还能保证新旧两份不会同时运行。
3. 迁移范围包括出口链路（mihomo、配置、上游候选池、relay 和内嵌 Python、启停/守护/监控脚本、系统代理/时区/浏览器模式脚本、精简后的托盘）、shim 与用户 PATH、AI 浏览器 profile、自启动项和指向旧目录的快捷方式。
4. 不迁移：Codex 渠道切换、ticket relay、Prism、Astra、Workbench 服务入口、各类 probe 和 TUN 脚本。这些留在旧目录，不停止、也不修改。
5. 二进制、凭据、profile、日志和内嵌运行时放在 gitignore 范围内；脚本可以入库，但提交前要用户确认。
6. 切换由一个自包含、需要管理员权限的脚本一次完成：停旧 → 起新 → 验证 → 失败自动回滚。执行期间 agent 不需要网络；旧目录的文件一律不改不删。
7. 新产品的开发实例使用另一组端口（17xxx），与 legacy 互不干扰。legacy 是全局状态的当前所有者，直到新产品按 ADR-0004 的接管门替换它。

## 后果

- 旧目录不再承载运行中的出口链路，但文件原样保留，回滚只需要恢复自启动项、PATH，并从旧目录重新启动。
- 新仓库会有一份暂时的 PowerShell/Python legacy 代码，它不属于新产品核心，也不受新产品的代码规范约束。替换完成后整体删除。
- 迁移本身需要一段停机窗口（停旧到起新），由切换脚本控制在分钟级以内，失败时自动恢复旧链路。
