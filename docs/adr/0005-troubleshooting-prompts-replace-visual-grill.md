# ADR-0005：用逐项排查提示词取代应用内可视化问答

- 状态：Accepted（替代原「可视化问答为主流程」的决定）
- 日期：2026-10-10

## 背景

原方案把应用内可视化问答（每轮 4–6 题、进度、暂存、返回修改）作为配置缺口的主流程，最后汇总成结构化提示词。2026-10-10 审阅验收清单时，用户明确表示：可视化问答可以不做，只要针对每个出问题的检查项，给出交给 agent 排查的提示词就够了。

## 决策

1. 第一版不实现可视化问答流程。
2. 首次配置用普通设置页表单直接编辑 AgentProfile 和 DailyProfile。
3. 每个状态为「失败」或「未知」的检查项、每个恢复失败项、每个设置缺项，都附一段可复制的「排查提示词」。内容包括：检查项、期望值、实际证据（来源和时间戳）、允许 agent 修改的本机范围、验证命令、回滚要求，以及不可修改的边界（旧目录、全局状态接管门等）。
4. 提供「复制全部问题」。生成和发送分离：应用只负责复制到剪贴板，不调用任何外部 Agent 或 API。
5. 提示词不能包含凭据、mihomo secret、Cookie 或长期标识；上游地址里的账号密码要脱敏。

## 后果

- 第一版 UI 工作量明显下降，引导数据结构变成「检查结果 → 提示词模板」的纯函数，好测试。
- 失去了逐题引导新手补全配置的体验；如果以后需要，可以在同一数据结构上加问答界面，不影响检查和提示词。
- 原文档中「可视化 Grill 问答」「每轮 4–6 题」等表述随本 ADR 一起改掉。
