# 无窗口排查与证据边界

当控制中心、浏览器窗口自动化或 Agent 会话出现卡住时，不要重复切换窗口、重启代理或覆盖系统代理。先运行发布包中的只读诊断；必须指定实际安装的数据目录。

```powershell
.\aec-agent.exe --data-dir 'D:\YourInstall\data' diagnose
```

安装版通常使用 `%LOCALAPPDATA%\AgentEgressController`；便携版使用程序旁的 `data`。命令最多等待十秒，不打开或聚焦窗口、不访问外网、不写目录/系统设置，不要求启用 Agent 控制。诊断访问正在运行的本机接口时会使用当前用户的凭据，但不会输出凭据、路径或地址。

输出是一个 JSON 对象：

- `status=observed` 只表示取得本机接口响应，不表示网络全通。
- `source=saved_state_only` 不是实时证据；状态未知不能变成通过。
- `profileValid` 表示结构校验，不能证明账号、套餐或出口可用。
- `mode`、`busy`、`fixedBlocked` 为能读取到的状态；null 表示无证据。
- `networkReadiness=unknown`：该命令不做网站或出口测试。
- `reason=diagnostic_timeout`：等待超过十秒；停止后续 UI 动作，保留该结果，避免把长时间挂起误报为联网问题。
- `version` 为诊断程序版本，不是已经运行的托盘版本。

无需复制完整 `state.json`、`profiles.json`、内核配置或日志；这些文件可能包含私人地址或令牌。分享诊断前仍应自行检查内容。程序不会自动发布诊断结果。

## 网络故障应分开验证

1. 确认本应用当前监听与系统代理归属，不直接写注册表或抢回代理。
2. 区分普通本机代理、固定 ISP、ISP 前面的中转路径。某站点能登录不等于后端 API、上传或长连接能用。
3. HTTPS 403 可能是挑战或访问策略；TCP/TLS 重置不能证明账号或 IP 被封禁。仅收到 200/302/403 也不证明登录或完整应用功能可用。
4. 用户要求改用非固定出口时，使用既有组快捷切换并明确范围；不能暗中把其他受保护站点也改道。

[事件原始记录](https://github.com/zxs4KHf/agent-egress-controller/issues/4)中的两次系统代理/时区快照一致，未进入 Agent 模式。之后一次外部 `sky.get_window_state` 未取得结果，约五分钟后被记录为失败。

**已确认**：窗口状态读取未正常返回；两次快照未发现系统写入。

**未确认**：VPN 是否实际断开、窗口读取是否隐式聚焦、责任组件及可复现条件。不能因会话中断就归因于本应用修改代理，也不能由早期快照推断之后网络一直正常。

0.5.1 提供不依赖窗口读取的十秒诊断入口、独立页面交互测试和慢请求隔离。这是项目侧的诊断替代与防阻塞措施，不是对外部窗口工具根因的修复证明。继续收集统一时间戳的工具错误和用户自行保存的网络事件摘要；仅在有备用联网及回滚条件的隔离环境比较窗口/DOM/无窗口路径，不在当前会话主动重现断网。Issue 保持待证据状态。
