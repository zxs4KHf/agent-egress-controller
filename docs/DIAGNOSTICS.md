# 无窗口排查与证据边界

当控制中心、浏览器窗口自动化或 Agent 会话出现卡住时，不要重复切换窗口、重启代理或覆盖系统代理。先运行发布包中的只读诊断；必须指定实际安装的数据目录。

```powershell
.\aec-agent.exe --data-dir 'D:\YourInstall\data' diagnose
```

安装版通常使用 `%LOCALAPPDATA%\AgentEgressController`；便携版使用程序旁的 `data`。命令最多等待十秒，不打开或聚焦窗口、不访问外网、不写目录/系统设置，不要求启用 Agent 控制。诊断访问正在运行的本机接口时会使用当前用户的凭据，但不会输出凭据、路径或地址。

输出是一个 JSON 对象：

- `status=observed` 只表示取得本机接口响应，不表示网络全通。
- `source=saved_state_only` 不是实时证据；状态未知不能变成通过。
- `profileValid` 表示结构校验，不能证明账号、套餐或出口可用。
- `mode`、`busy`、`fixedBlocked` 为能读取到的状态；null 表示无证据。
- `networkReadiness=unknown`：该命令不做网站或出口测试。
- `reason=diagnostic_timeout`：等待超过十秒；停止后续 UI 动作，保留该结果，避免把长时间挂起误报为联网问题。
- `version` 为诊断程序版本，不是已经运行的托盘版本。

无需复制完整 `state.json`、`profiles.json`、内核配置或日志；这些文件可能包含私人地址或令牌。分享诊断前仍应自行检查内容。程序不会自动发布诊断结果。

## 网络故障应分开验证

1. 确认本应用当前监听与系统代理归属，不直接写注册表或抢回代理。
2. 区分普通本机代理、固定 ISP、ISP 前面的中转路径。某站点能登录不等于后端 API、上传或长连接能用。
3. HTTPS 403 可能是挑战或访问策略；TCP/TLS 重置不能证明账号或 IP 被封禁。仅收到 200/302/403 也不证明登录或完整应用功能可用。
4. 用户要求改用非固定出口时，使用既有组快捷切换并明确范围；不能暗中把其他受保护站点也改道。

## 系统代理变化、G3 与网页 DNS 泄露

AEC 的 mixed 入口与 Clash 的 mixed 入口可以是不同端口；不同端口同时监听不是抢端口。真正的端口冲突须有同一监听地址/端口的占用或 bind 失败证据。Windows 系统代理只有一份，某客户端把它改为自己时，普通浏览器就可能绕过 AEC；CLI 的代理环境变量仍可指向 AEC，所以浏览器能用不代表 Codex 使用同一路径。

AEC 不循环抢回系统代理。受支持的共存方式是其他客户端只运行本地内核，由 AEC 作为唯一系统代理入口，并在 AEC 中选择其普通上游端口。需要保留其他客户端系统代理开关时，不能声称 AEC 的应用内规则仍覆盖所有流量。独立指纹浏览器的代理与 Arena profile 不由 AEC 自动接管。

G3 只检查本轮测试请求在内核中记录的域名与出站。日志不可读、没有新连接记录时为未知，不证明已经发生本地 DNS 泄露；0.5.6 修复启动跨 UTC 日期的日志定位与检测请求连接池复用。修复 G3 不等于修复网页 DNS 检测。

网页显示境外业务出口、国内递归解析器时，应继续核对 Windows/浏览器 DNS、所用代理内核的 DNS 与实测请求路径，不能把“可能泄露”忽略成纯 UI 问题。HTTPS/HTTP CONNECT 只改变应用连接路径，不自动接管整机 DNS。mihomo 的 `nameserver` 用于域名解析，DNS 连接遵循路由需要 `respect-rules`，并应配置 `proxy-server-nameserver` 避免解析代理节点的循环依赖；仅换一个 DNS 地址也不能保证走指定出口。见 [mihomo 官方 DNS 配置](https://wiki.metacubex.one/config/dns/)。

未经用户确认，不修改其他客户端、Windows DNS 或浏览器隐私策略。不要为验证泄露而停掉当前唯一联网路径；不要将网页的分数当作 OpenAI 的内部风险结论。
