本机 Agent 控制

MCP 与 HTTP/JSON 共用这个开关。

控制权限与安全边界

开启后，同一 Windows 用户运行的 Agent 可读取设置、管理规则与路径、进入和退出模式、管理自启与快捷方式。固定出口约束始终有效。关闭立即拒绝新请求，已经接受的操作会完成。密码只在本机出口设置页输入，不进入 Agent 配置或聊天；认证不隔离同一用户下的恶意程序。

1注册 MCP

把下面配置添加到支持本机 stdio MCP 的客户端。托盘需保持运行；部分客户端需要重启后加载配置。

客户端不支持本机 MCP？
可让本机 Agent 执行发布包内的 aec-agent.exe call，从标准输入传入 JSON。纯云端 Agent 无法直接访问本机，需要可信的本机执行工具。


2给 Agent 的任务说明
请先读取 aec_options、aec_state、aec_settings，再按我的要求配置 AEC。
始终保持我指定的 ISP 出口 IP，未知证据不能报告为通过。
密码由我在本机设置页填写，不进入聊天。
进入或切换后读取真实状态并说明检测结果。核心升级会停止服务，必须先让我确认。
先区分站点协作与旧系统接管：协作模式保留 Clash 的系统代理、普通规则与节点，不抢写开关；旧 AEC 接管模式才需要关闭其他客户端系统代理。
协作先读 aec_cooperation_state，获准所选站点后预览/安装精确 planId，不覆盖自定义脚本，不自动重载 Clash；激活由我在客户端完成。
DNS/ECS 外网探针需我单独同意，结果只代表该次查询。固定入口、规则存在与浏览器全部无泄露是不同证据。
不修改独立指纹浏览器的 profile、节点和出口。


高级：HTTP / JSON 接口
发现文件 agent-api.json 只保存端口和凭据引用。桥接程序从当前用户 Windows Credential Manager 读取临时 Bearer 令牌；请勿把令牌写入配置、URL 或聊天。
POST http://127.0.0.1:<port>/api/v1/call
Authorization: Bearer <本机读取的临时令牌>
Content-Type: application/json

{"name":"aec_state","arguments":{}}
使用精确的 loopback Host 与 Content-Length，不发送 Origin；协议和工具以 aec_options 为准。推荐使用随包桥接程序。
