普通网站继续由当前系统代理自动分流；只有明确选定的站点转交 AEC 固定 ISP。GPT 不绑定某家代理，Arena 和独立指纹浏览器不自动纳入。

局部脚本导出不代表已安装或已保护

AEC 不循环抢回系统代理，也不因“生成成功”就显示固定出口、DNS 或浏览器环境全部通过。客户端挂载、激活及运行规则核对仍是单独步骤，不能自动覆盖已有订阅脚本。

开关与启动顺序

在出口设置选择“站点协作”，同时关闭 AEC 的系统代理接管选项。进入 Agent 模式与打开 Clash 系统代理的先后顺序不限；要让日常浏览器经过规则，Clash 系统代理须保持开启。

关闭 Clash 系统代理后浏览器会绕过其规则，需要代理的普通网站可能不通，固定站点也不再受此入口保护。AEC 不会抢回开关；重新开启后 G7 重新读取入口和规则，不使用旧的通过结果。此方案没有系统级强制阻断绕过能力。

Clash Verge Rev 2.5.8 默认 named pipe 可直接核对，不需要额外开启 TCP controller。当前规则没有 AEC-MANAGED-FIXED 时，Claude 固定转发尚未生效。普通 IP 检测网页遵循 Clash 原规则，不能用它的 IP 判断所有站点出口。

所选站点的连接路径

浏览器 → 当前系统代理客户端 → AEC 固定专用入口 → 原 ISP。其他网站继续走客户端原规则，不需要反复更换系统代理端口。

  1. 在支持的 Clash Verge Rev 中保留系统代理开关，使用规则模式。全局/直连模式会绕开域名规则；TUN、裸 IP 和其他绕过路径不能按这份脚本声称已保护。
  2. 在 AEC 看板维护受保护站点，并填写原固定 ISP 的精确预期 IP。不要把 cloud.ai 当作 claude.ai 自动加入。
  3. 生成局部订阅脚本。它只包含选定域名的固定转发、UDP 拒绝、局部 DoH 策略和本机固定入口，不包含节点密钥或控制令牌。
  4. 通过客户端官方订阅扩展入口，在最后一步挂载。已有脚本先保留并正确组合，不能直接覆盖。应用配置可能短暂中断连接，先确认后再激活。
  5. 实际核对当前订阅的脚本、规则模式和固定身份。订阅刷新、切换或客户端升级后再次核对；不支持的客户端保持未验证。

AEC 旧“接管系统代理”与客户端协作是不同配置。生成脚本不会替你转换运行模式，也不会停止旧会话。改变当前核心或接管范围前，须展示计划并单独确认。

DNS、UDP、WebRTC 和 ECS 的验证边界

所选域名使用经固定专用入口的 DoH，路径失败不回退普通 DNS。已识别域名的 UDP 在转发规则之前拒绝；不能依赖 HTTP 不支持 UDP 来防止回退。裸 UDP、浏览器预解析和独立 DNS 必须另行验证。

G3 是检测请求的内核路径证据，不是整机泄露保证。DNS 传输、解析器和 EDNS Client Subnet（ECS）分项显示；没有实际查询或权威端证据就是未知。WebRTC 没有 ICE 候选也不能直接判定无泄露。

浏览器环境区分“仅 AI 浏览器”和“全局浏览器”；后者需逐项展示影响并确认。尚未接入的策略不显示为已应用。系统时区是整机状态，不是按网站独立设置。

兼容模式：由 AEC 接管系统代理

继续使用旧接管模式时，另一客户端只运行本地内核作为 AEC 普通上游，不能同时抢写系统代理。客户端内照常切节点，受保护站点仍在 AEC 内固定。两种模式不能靠反复开关混用。

G6 提示系统代理已改变时，AEC 保留外部设置并撤销就绪，不循环抢写。端口冲突须有同地址同端口占用证据；节点错误不能全部归因于系统代理冲突。
