Agent 接入

返回看板 · 出口与密钥设置 · 代理冲突说明

1. 开启本机控制

默认关闭。开启后，同一个 Windows 用户运行的 Agent 可读取配置、切换路径、编辑规则、进入和退出 Agent 模式、管理自启和快捷方式。切换允许断连，固定出口核对失败仍保持阻断。

关闭后拒绝新请求，已经执行的操作会完成；退出托盘会停止接口并删除本次令牌。认证令牌只存在 Windows 凭据管理器，配置里没有密钥。同一用户的恶意程序不在该隔离能力范围内。

2. 给 Agent 注册 MCP

复制下面配置到支持本机 stdio MCP 的 Agent 客户端。无需 Node、Python、SDK、管理员权限或源码。托盘需保持运行。不同客户端的注册文件格式可能不同，下面是通用 MCP server 条目；某些客户端需要重启才能加载 MCP。

不支持本机 MCP 的客户端：让 Agent 执行发布包内的 aec-agent.exe call，JSON 从标准输入传入。纯云端 Agent 无法直接访问你的本机，需要本机执行工具或支持 MCP 的桌面客户端。


3. 让 Agent 开始工作
请通过 agent-egress-controller 的工具先读取 aec_options、aec_state、aec_settings。
按我的要求配置分流规则、连接路径和自启。保持我指定的 ISP 出口 IP，检测未知不可算通过。
需要密码时让我在本机出口设置页填写，不要让我把密码粘贴进聊天。
进入或切换后再读取 aec_state，说明实际检测结果，不要只凭操作完成就说已就绪。
如果系统代理被 Clash 等客户端改写，请解释冲突并让我关闭它的系统代理开关；保留它的内核端口作为普通流量上游，可继续切节点。


HTTP / JSON 接口
自定义本机 Agent：发现文件是数据目录下的 agent-api.json，包含随机端口、协议版本和 credentialRef，不含令牌。用当前用户 Credential Manager 读取 AgentEgressController:<credentialRef> 的 UTF-16 密码，作为 Bearer 请求头。
POST http://127.0.0.1:<port>/api/v1/call
Authorization: Bearer <本机读取的令牌>
Content-Type: application/json

{"name":"aec_state","arguments":{}}
必须使用精确的 Host 和 Content-Length，不发送 Origin、不使用浏览器跨域。返回 {ok,result} 或 {ok:false,error}。协议、工具和能力以 aec_options 为准。推荐使用桥接程序，避免自行处理令牌。
